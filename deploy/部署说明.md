# 云服务器部署说明

当前部署方式使用 HTTP，适合测试和简历演示。云服务器只需要向公网开放 SSH 和 `80`，不要开放 `3306`、`8080`、`8081`。

## 1. 环境要求

- Linux 云服务器
- Docker Engine
- Docker Compose v2
- Git
- Nginx（安装在宿主机，监听公网 `80`）

## 2. 首次部署

```bash
git clone <你的仓库地址> mall-test-system
cd mall-test-system/deploy
cp .env.example .env
```

生成三个不同的密码：

```bash
openssl rand -base64 32
openssl rand -base64 32
openssl rand -base64 24
```

编辑 `.env`，依次填写 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD` 和 `ADMIN_PASSWORD`。三个密码都不能留空，也不要把 `.env` 提交到 GitHub。

```bash
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Compose 会将 Docker 前端 Nginx 绑定到宿主机的 `127.0.0.1:8081`。该地址只能从服务器本机访问，避免容器端口直接暴露到公网。先在服务器本机确认 Docker 前端正常：

```bash
curl http://127.0.0.1:8081/
```

如果修改了 `.env` 中的 `HTTP_PORT`，下面 Nginx 配置里的转发端口也必须同步修改。

然后创建宿主机 Nginx 配置 `/etc/nginx/conf.d/mall-test-system.conf`：

```nginx
server {
    listen 80;
    server_name _;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

检查配置并重新加载宿主机 Nginx：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

如果 Nginx 报 `80` 端口或默认站点冲突，应先检查现有站点配置，确认没有其他业务依赖后再调整冲突的 `server` 配置。

完成后访问：`http://服务器公网IP/`

管理员用户名为 `admin`，密码是 `.env` 中的 `ADMIN_PASSWORD`。普通测试用户仍为 `user / 123456`。

## 3. 端口

| 端口 | 绑定方式 | 用途 |
| --- | --- | --- |
| `80` | `0.0.0.0` | 宿主机 Nginx 公网入口，需要在安全组开放 |
| `8081` | `127.0.0.1` | Docker 前端 Nginx，由宿主机 Nginx 转发 |
| `8080` | `127.0.0.1` | 后端调试，只能从服务器本机访问 |
| `3306` | `127.0.0.1` | MySQL，只能从服务器本机访问 |

公网请求链路为：

```text
浏览器 -> 云服务器公网 80 -> 宿主机 Nginx -> 127.0.0.1:8081 -> Docker 前端 Nginx
                                                        -> /api -> Spring Boot
```

服务器本机可以检查前端和后端健康状态：

```bash
curl http://127.0.0.1:8081/
curl http://127.0.0.1:8080/actuator/health
```

## 4. 更新代码

本地修改完成并推送到 GitHub 后，在云服务器执行：

```bash
cd /opt/mall-test-system
git pull origin main
cd deploy
docker compose up -d --build
docker compose ps
```

`up -d --build` 会重建有变化的前后端容器，不会删除 MySQL 数据卷。

## 5. 日志和排查

```bash
docker compose ps
docker compose logs --tail=100 backend
docker compose logs --tail=100 nginx
docker compose logs --tail=100 mysql
```

Compose 已限制每个容器日志最多保留 `3 x 10 MB`。

## 6. 数据库规则

MySQL 只会在空数据卷首次创建时执行 `sql/init.sql`。上传新代码不会同步本机数据库，修改 `init.sql` 也不会自动更新已有数据。

需要保留本机数据时，应先使用 `mysqldump` 导出，再导入云服务器容器。部署更新时不要执行：

```bash
docker compose down -v
```

该命令会删除 `mall_mysql_data` 数据卷。只有确认不需要任何云端数据时才可用它重置测试环境。

如果服务器已经使用过旧版 Compose，旧数据卷中不会自动创建 `mall_app` 数据库账号。应先备份数据库，再手动创建该账号；没有需要保留的数据时也可以删除旧数据卷后重新初始化。

## 7. 密码兼容

- 新注册用户使用 BCrypt 保存密码。
- `init.sql` 中的测试账号密码已经是 BCrypt 哈希。
- 旧数据库中的明文密码会在应用启动时自动转成 BCrypt。
- 每次启动都会确保管理员密码与 `.env` 中的 `ADMIN_PASSWORD` 一致。
