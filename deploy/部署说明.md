# 云服务器部署说明

当前部署方式使用 HTTP，适合测试和简历演示。云服务器只需要向公网开放 SSH 和 `80`，不要开放 `3306`、`8080`。

## 1. 环境要求

- Linux 云服务器
- Docker Engine
- Docker Compose v2
- Git

## 2. 首次部署

```bash
git clone <你的仓库地址> mall-test-system
cd mall-test-system/deploy
cp .env.example .env
```

生成三个不同的密码：

```bash
openssl rand -base64 32
openssl rand -base64 32
openssl rand -base64 24
```

编辑 `.env`，依次填写 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD` 和 `ADMIN_PASSWORD`。三个密码都不能留空，也不要把 `.env` 提交到 GitHub。

```bash
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

访问：`http://服务器公网IP/`

管理员用户名为 `admin`，密码是 `.env` 中的 `ADMIN_PASSWORD`。普通测试用户仍为 `user / 123456`。

## 3. 端口

| 端口 | 绑定方式 | 用途 |
| --- | --- | --- |
| `80` | `0.0.0.0` | 前端和 `/api`，需要在安全组开放 |
| `8080` | `127.0.0.1` | 后端调试，只能从服务器本机访问 |
| `3306` | `127.0.0.1` | MySQL，只能从服务器本机访问 |

服务器本机可以检查后端健康状态：

```bash
curl http://127.0.0.1:8080/actuator/health
```

## 4. 更新代码

本地修改完成并推送到 GitHub 后，在云服务器执行：

```bash
cd /opt/mall-test-system
git pull origin main
cd deploy
docker compose up -d --build
docker compose ps
```

`up -d --build` 会重建有变化的前后端容器，不会删除 MySQL 数据卷。

## 5. 日志和排查

```bash
docker compose ps
docker compose logs --tail=100 backend
docker compose logs --tail=100 nginx
docker compose logs --tail=100 mysql
```

Compose 已限制每个容器日志最多保留 `3 x 10 MB`。

## 6. 数据库规则

MySQL 只会在空数据卷首次创建时执行 `sql/init.sql`。上传新代码不会同步本机数据库，修改 `init.sql` 也不会自动更新已有数据。

需要保留本机数据时，应先使用 `mysqldump` 导出，再导入云服务器容器。部署更新时不要执行：

```bash
docker compose down -v
```

该命令会删除 `mall_mysql_data` 数据卷。只有确认不需要任何云端数据时才可用它重置测试环境。

如果服务器已经使用过旧版 Compose，旧数据卷中不会自动创建 `mall_app` 数据库账号。应先备份数据库，再手动创建该账号；没有需要保留的数据时也可以删除旧数据卷后重新初始化。

## 7. 密码兼容

- 新注册用户使用 BCrypt 保存密码。
- `init.sql` 中的测试账号密码已经是 BCrypt 哈希。
- 旧数据库中的明文密码会在应用启动时自动转成 BCrypt。
- 每次启动都会确保管理员密码与 `.env` 中的 `ADMIN_PASSWORD` 一致。
