# mall-test-system V2 测试需求分析

## 1. 目标与边界

系统用于软件测试实习项目，重点验证业务规则、状态流转、权限边界、参数校验和数据库一致性。保留商品、购物车、订单功能，不包含优惠券、秒杀、真实支付、退款、评价、Redis 或消息队列。

## 2. 功能需求

| 编号 | 模块 | 需求与验收点 |
| --- | --- | --- |
| R001 | 认证 | 注册用户角色固定为 USER；启用用户可登录，禁用用户登录返回 403 |
| R002 | 权限 | 未登录访问受保护接口返回 401；普通用户访问 `/api/admin/**` 返回 403 |
| R003 | 地址 | 用户可新增、修改、删除、查询和设置自己的默认地址 |
| R004 | 地址 | 收货人、手机号、省市区、详细地址必填并满足长度限制；同一用户最多一个默认地址 |
| R005 | 地址 | 操作其他用户地址时不暴露数据，返回 404 |
| R006 | 商品 | 前台只展示未删除且上架商品；零库存商品不可成功加入购物车或下单 |
| R007 | 商品 | 删除使用软删除；软删除商品不在默认管理员列表，且不能编辑、改库存或重新上架 |
| R008 | 购物车 | 数量必须大于 0 且不能超过当前库存；用户只能操作自己的条目 |
| R009 | 下单 | 创建订单必须传 `addressId`，地址必须属于当前用户 |
| R010 | 下单 | 下单锁定商品、校验状态和库存、扣减库存、保存商品及地址快照，并删除对应购物车条目 |
| R011 | 状态 | `CREATED` 仅可支付或取消；取消只恢复一次库存 |
| R012 | 状态 | `PAID` 仅管理员可发货；发货必须包含物流公司和物流单号 |
| R013 | 状态 | `SHIPPED` 仅订单所属用户可确认收货并变为 `COMPLETED` |
| R014 | 状态 | `PAID`、`SHIPPED`、`COMPLETED` 不可取消；`CANCELLED` 不可支付 |
| R015 | 状态 | 重复支付、取消、发货、确认收货返回明确 400 错误 |
| R016 | 日志 | 创建、支付、发货、完成、取消均记录原状态、新状态、操作人、时间和备注 |
| R017 | 查询 | 用户订单列表支持状态筛选和分页 |
| R018 | 查询 | 管理员订单支持订单号、用户名、状态、开始/结束时间组合查询和分页 |
| R019 | 用户管理 | 管理员可分页查询、启用和禁用普通用户，不能修改管理员状态 |
| R020 | 校验 | 非法分页、参数类型错误、错误 JSON 返回统一格式 400 |
| R021 | 响应 | 资源不存在返回 404；所有业务接口返回 `code/message/data` 结构 |

## 3. 状态机

```text
CREATED -> PAID -> SHIPPED -> COMPLETED
   |
   +------> CANCELLED
```

除图中路径外的状态变更均为非法操作。状态变更前必须锁定订单记录，状态更新和日志插入必须在同一事务内提交或回滚。

## 4. 数据一致性需求

- 订单取消时先锁订单，再按商品 ID 顺序锁商品并恢复库存。
- 同一订单在并发取消请求下只能有一个请求成功，库存只增加一次。
- 地址默认状态在用户级写锁内修改，数据库通过生成列唯一索引限制同一用户最多一个默认地址。
- `orders` 保存完整收货地址快照；`address_id` 不设置外键，允许源地址删除。
- 商品删除只更新 `deleted/deleted_at/status`，历史订单明细仍保留商品快照。

## 5. 参数与边界

| 字段 | 规则 |
| --- | --- |
| 用户名 | 必填，3-50 字符 |
| 密码 | 必填，6-100 字符 |
| 商品名 / 分类 | 必填，分别最多 100 / 50 字符 |
| 图片地址 / 描述 | 最多 500 / 1000 字符 |
| 收货人 | 必填，2-50 字符 |
| 手机号 | 必填，6-20 字符 |
| 省 / 市 / 区 | 必填，各最多 50 字符 |
| 详细地址 | 必填，5-200 字符 |
| 物流公司 / 物流单号 | 必填，各最多 100 字符 |
| page | 大于等于 1 |
| size | 1-100 |

## 6. 初始化数据

- `user / 123456`：启用普通用户。
- `admin / 123456`：管理员。
- `disabled_user / 123456`：禁用普通用户。
- 两条普通用户地址，其中一条默认地址。
- 正常库存、低库存、零库存、下架和软删除商品。
- 五种订单状态各一条，并带对应状态日志与地址快照。

## 7. 接口约束

接口清单、请求体和查询参数以 Swagger `v2.0.0` 与项目 README 为准。Postman Collection 使用 `userToken` 和 `adminToken` 分离权限场景，不把任何执行数量或通过率写入文档。
