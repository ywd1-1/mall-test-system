# 测试总结报告

## 1. 项目概述

mall-test-system V2 是一个前后端分离的电商订单管理系统。本轮测试围绕用户认证、商品、购物车、收货地址、订单状态流转、后台管理、权限控制和库存一致性展开，并补充了 Postman/Newman 接口回归与并发下单验证。

## 2. 测试环境

| 项目 | 内容 |
| --- | --- |
| 测试日期 | 2026-07-22 |
| 前端 | Vue 3 + Vite + Element Plus |
| 后端 | Spring Boot 2.7 / Java 8 |
| 数据库 | MySQL 8.0 / InnoDB |
| 部署方式 | Docker Compose + Nginx |
| 接口工具 | Postman + Newman |
| 并发工具 | JMeter |

## 3. 测试范围

- 用户登录、注册、Token 与角色权限
- 商品查询、上下架、库存边界和软删除
- 购物车增删改查与库存约束
- 收货地址增删改查、默认地址与归属校验
- 创建订单、支付、取消、发货和确认收货
- 订单状态机、状态时间线、地址快照与商品快照
- 管理员商品、用户和订单管理
- 重复操作、越权访问、非法参数和统一异常响应
- 两个用户并发购买最后一件商品时的库存一致性

## 6. 典型缺陷

| 编号 | 问题描述 | 当前状态 |
| --- | --- | --- |
| BUG-001 | 商品库存输入小数时仍保存成功，并被截断为整数 | 已修复，回归测试通过 |
| BUG-002 | 购物车未勾选商品时仍按全部商品创建订单 | 已修复，回归测试通过 |

两个缺陷均完成前后端防御性修复并通过回归验证，详细步骤、实际结果、预期结果和修复方案见《缺陷用例.xlsx》。

## 7. 专项验证结果

- 使用 Postman 环境变量分别保存管理员和普通用户 Token，并通过 Newman 批量执行 52 个请求项。
- Newman 共执行 13 条核心断言，最终失败数为 0。
- 使用 JMeter 同步定时器模拟两个用户同时购买库存为 1 的商品，结果为一个请求成功、一个请求库存不足，最终未发生超卖。
- 功能用例保留两条缺陷回归记录和一条并发验证记录，未覆盖首次失败历史。

## 8. 风险说明

- 当前支付为模拟支付，未接入真实支付渠道。
- Token 保存在后端内存中，服务重启后需要重新登录。
- 初始化账号使用测试环境弱口令，云部署时应通过 `.env` 覆盖管理员密码。
- 本轮 Newman 执行为功能性接口回归，不能替代完整的性能、容量和安全测试。
- 退款、优惠券、评价、秒杀、Redis 和消息队列不在本轮测试范围内。

## 9. 测试结论

本轮计划范围内的核心功能、接口、权限控制、订单状态流转和库存一致性均通过验证。累计发现的 2 个高优先级缺陷已修复并完成回归，当前无阻塞缺陷；项目达到本轮测试范围内的发布条件。
